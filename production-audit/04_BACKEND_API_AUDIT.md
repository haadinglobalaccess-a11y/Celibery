# 04 — Backend API Audit (Node.js + Express)

## 1. Reliability

| Area | Implementation | Assessment |
|---|---|---|
| Async errors | `ah()` wrapper sends rejections to `errorHandler` (`lib/http.ts`) | PASS |
| Error envelope | `{ ok:false, error:{ code, message, details? } }`. 500s return only a request id; stacks go to logs (`middleware/error.ts`) | PASS |
| Mongoose errors | Validation → 400, CastError → 400 `INVALID_ID`, duplicate key → 409, bad JSON → 400, too large → 413 | PASS |
| Library 4xx (`expose:true`) | Kept as 4xx with one warn line (prevents 500/log flooding) | PASS |
| Timeouts | Server `headersTimeout` 20 s, `requestTimeout` 120 s, keep-alive 65 s; gateway calls 20 s; Mongo `serverSelectionTimeoutMS` 10 s, `waitQueueTimeoutMS` 10 s | PASS |
| DB outage | `databaseGate`: waits ≤ 2 s for reconnect, then 503 `DATABASE_UNAVAILABLE` with `Retry-After`, except a short allow-list of cached public GETs | PASS (unit and integration tested) |
| Process | `unhandledRejection` is logged without crashing. `uncaughtException` is reported, then the process exits (the host restarts it). Graceful SIGTERM drains for ≤ 10 s | PASS |
| CORS | Explicit allow-list. Credentials on. Preflight cached 2 h. LIVE: a foreign origin gets no ACAO | PASS |
| Versioning | None (`/api/*`). Acceptable while the only client is the bundled SPA | INFO |

## 2. Input validation
Every route uses `validate(zodSchema, part)`. Zod strips unknown keys, so body, query and params are replaced by parsed values. As defence in depth, `rejectOperatorKeys` blocks `$…`, `__proto__`, `constructor` and `prototype` keys at any depth, and `mongoose.set('strictQuery', true)` is on. Checked samples:

- Checkout (`order.schemas.ts`): ObjectId regex, quantities 1–99, ≤ 50 lines, Saudi phone regex, postal code, short address, idempotency key 16–80 chars `[A-Za-z0-9_-]`, payment-method enum.
- Auth: email normalised; password 8–128 chars and ≤ 72 UTF-8 bytes (the bcrypt truncation limit is handled correctly).
- Admin refund: integer halalas ≥ 1, reason 2–300 chars, optional idempotency key.
- Uploads: declared type and size checked by `validateUploadParts`; content verified by magic bytes (`media-sniff.ts`); SVG, HTML, PDF and archives rejected; storage keys generated by the server and regex-checked (`safeKey`).

**Assessment: PASS.** I found no route that builds a query from unvalidated input.

## 4. API security controls

| Control | Status | Notes |
|---|---|---|
| Authentication middleware | PASS | JWT HS256 (algorithm pinned) referencing a server-side `Session`; checks `tokenVersion`, type, active and revocation on every request |
| Authorisation | PASS | `requireStaff` on `/admin`; `requirePermission` per route or router (all ~120 admin routes checked) |
| Rate limiting | PASS | Global 300/min/instance; Mongo-backed shared limits for auth (20/15 min/IP), per-account failed login (10/15 min), reset email (5/h/address), MFA, checkout (20/min), quote (60/min), tracking (30/15 min), search, reviews, uploads |
| Body size | PASS | 1 MB JSON; raw uploads capped by the media limits |
| Security headers | PASS | LIVE API: CSP `default-src 'none'`, HSTS, nosniff, `X-Frame-Options`, no `X-Powered-By` |
| NoSQL injection | PASS | Zod + operator-key rejection + `strictQuery` |
| XSS (server-rendered HTML) | PASS | `prerender.ts` escapes every interpolation (`esc`); JSON-LD escapes `<` |
| CSRF | PASS for browser flows / **FAIL for webhooks (H-01)** | The custom-header requirement blocks the gateways as well |
| SSRF | PASS | All outbound fetches go to fixed hosts (gateways, Resend, WhatsApp Graph, S3 endpoint from env, oEmbed for YouTube/Vimeo only). Admin media URLs are never fetched by the server |
| Uploads | PASS | Magic-byte sniffing, size limits, server keys, served with a `MEDIA_CSP` sandbox and nosniff |
| Error leakage | PASS | Generic 500 with a request id |
| Brute force | PASS | Per-IP + per-account limits, 5-failure lockout (see M-06 for the trade-off) |

## 5. Endpoints exposing excessive data
None found. `toCustomerOrder` strips internal notes and history. Public product views use `PUBLIC_PRODUCT_FIELDS`. The public settings endpoint exposes only storefront settings: business identity (currently blank), social links and commerce rules, with no credentials (credentials are encrypted and never returned; `gatewayDiagnostics` returns booleans only).

## 6. Findings
- **H-01**: webhook CSRF exemption never matches (`security.ts:16`).
- **H-02**: webhook callback URL on the storefront host.
- **M-01**: refunds without step-up.
- **M-04**: test helper hides header-dependent bugs.
